# Contributing Guide

Thank you for your interest in contributing to the Fix Social Media Resource List! This guide will help you get started.

## 🌟 Ways to Contribute

There are many ways to contribute to this project:

- **Add new resources** - Share tools, extensions, or resources you've found useful
- **Update existing entries** - Keep information current and accurate
- **Improve documentation** - Enhance guides, fix typos, or clarify instructions
- **Report issues** - Let us know about broken links or outdated information
- **Suggest improvements** - Share ideas for better organization or new categories

## 📋 Before You Start

1. **Search first** - Check if the resource already exists in [RESOURCES.md](RESOURCES.md)
2. **Verify quality** - Ensure the resource is legitimate, functional, and relevant
3. **Test if possible** - Try the tool or extension yourself before submitting
4. **Check licensing** - Prefer open-source and well-licensed resources

## ✏️ How to Add a Resource

### Step 1: Fork and Clone

```bash
# Fork the repository on GitHub, then:
git clone https://github.com/YOUR-USERNAME/ressource-list.git
cd ressource-list
git checkout -b add-resource-name
```

### Step 2: Add Your Resource

1. Open `RESOURCES.md`
2. Find the appropriate category (or suggest a new one)
3. Add your resource following the existing table format
4. Include all required information:
   - **Name**: The official name of the tool/resource
   - **Description**: A brief, clear description (1-2 sentences)
   - **Platform/Browser**: Supported platforms or browsers
   - **Link**: Official website or repository URL
   - **License** (if applicable): Open source license type

### Step 3: Follow Formatting Guidelines

- Use proper markdown table syntax
- Keep descriptions concise (under 100 characters preferred)
- Use HTTPS links when available
- Alphabetize entries within categories when possible
- Ensure links are valid and point to official sources

#### Example Entry

```markdown
| Content Detective | AI-generated content detection browser extension | Chrome, Firefox | https://example.com/content-detective |
```

### Step 4: Commit Your Changes

```bash
git add RESOURCES.md
git commit -m "Add [Resource Name] to [Category]"
git push origin add-resource-name
```

### Step 5: Submit a Pull Request

1. Go to your fork on GitHub
2. Click "New Pull Request"
3. Fill in the PR template:
   - Describe the resource you're adding
   - Explain why it's valuable
   - Note if you've personally tested it
4. Submit the pull request

## 🎯 Contribution Guidelines

### Quality Standards

Resources should:
- ✅ Be functional and actively maintained
- ✅ Have a clear purpose related to improving social media
- ✅ Be safe and trustworthy
- ✅ Have proper documentation
- ✅ Respect user privacy

Resources should NOT:
- ❌ Be malware, scams, or deceptive
- ❌ Require payment without clear value
- ❌ Violate terms of service of major platforms
- ❌ Collect unnecessary personal data
- ❌ Be abandoned or non-functional

### Content Guidelines

- **Be objective**: Describe what the tool does, not why it's "the best"
- **Be concise**: Keep descriptions brief and informative
- **Be accurate**: Verify all information before submitting
- **Be respectful**: Follow our [Code of Conduct](CODE_OF_CONDUCT.md)

### Suggesting New Categories

If none of the existing categories fit your resource:

1. Create an issue describing the new category
2. Explain why it's needed
3. Provide examples of resources that would fit
4. Wait for community feedback before adding

## 🔍 Review Process

1. **Automated checks**: PRs are automatically checked for formatting
2. **Community review**: Other contributors may review and comment
3. **Maintainer approval**: A maintainer will review and merge approved changes
4. **Typical timeframe**: Most PRs are reviewed within 1-3 days

## 📝 Updating Existing Resources

Found outdated information? Here's how to update it:

1. Make the necessary changes in `RESOURCES.md`
2. Commit with a descriptive message: `Update [Resource Name] - [what changed]`
3. Submit a PR explaining the update

## 🐛 Reporting Issues

If you find problems but can't fix them yourself:

1. Check if an issue already exists
2. Create a new issue with:
   - Clear title
   - Description of the problem
   - Steps to reproduce (if applicable)
   - Suggested solution (if you have one)

## 💬 Getting Help

- **Questions?** Open a discussion in GitHub Discussions
- **Stuck?** Comment on your PR and ask for help
- **Ideas?** Share them in GitHub Issues

## 🙏 Recognition

All contributors are recognized in our project. Your contributions help make social media better for everyone!

## 📜 Code of Conduct

Please read and follow our [Code of Conduct](CODE_OF_CONDUCT.md). We are committed to providing a welcoming and inclusive environment for all contributors.
